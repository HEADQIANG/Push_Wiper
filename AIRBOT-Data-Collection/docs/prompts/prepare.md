# 前置要求

下面这些前置要求非常重要，请务必牢记并严格遵守！

## env

- 运行Python命令前，请先激活conda环境`airbot_play_data`。注意不需要额外创建虚拟环境！！
- 运行可能涉及下载（如数据集、模型）的命令前，请先执行`export {HTTP_PROXY,HTTPS_PROXY,ALL_PROXY,http_proxy,https_proxy,all_proxy}=http://127.0.0.1:7890`配置终端代理。

## package

- 遇到缺失的Python包时，请直接通过pip安装，如果pip找不到对应包，请立刻停止操作并通知我处理。
- 除非特别说明，否则请全局import，不要使用动态import来掩盖包找不到的问题，不要自己想当然额外处理包缺失的情况，要保持程序的简洁性。

## 路径

如果遇到所给的路径不存在或错误，请立刻停止操作并通知我处理。

## 注释

- 类中各个方法要有docstring注释，注释内容要简洁明了，能让人快速理解方法功能和参数含义即可。
- 数据类各字段下方使用docstring对该字段进行说明，不要在类级别注释中重复说明，也不要在字段上方使用#注释重复说明。
- 注释使用英文。

# 类型注解

- 不要使用`from __future__ import annotations`，返回自身类型时请使用`from typing_extensions import Self`。
- 不要使用`|`以及原始类型（如`list`、`dict`等）等进行类型注解，兼容Python 3.7及以上版本。

## 风格

- 力求代码的简洁，除非有明确指示，否则不要添加额外的版本兼容等繁琐代码。
- 自定义类如果需要初始化参数，只允许使用一个`config`参数，且该参数必须是继承自`pydantic.BaseModel`（注：BaseModel支持可变类型直接赋值，不需借助`Field`，其默认行为是浅拷贝）。
- 数据类必须使用`pydantic.BaseModel`，禁止使用`dataclasses`模块。
- 脚本文件的命令行传参使用`pydantic_settings`库实现。
- 尽可能模块化、可复用，避免冗长的函数和类，避免重复冗余的代码。例如，各种配置类、命令行参数类等应根据层级关系进行继承，而不是在每个类中重复定义相同的配置项。命令行参数类应尽可能复用已有的配置类，而不是重新定义相同的配置项。
- 当函数返回的值较多时，应使用`NamedTuple`或数据类进行封装，而不是返回多个值的元组或字典。

## 测试

- 除非有明确指示要求，否则请不要改动任何现成的测试代码。不要在通用的测试程序中为某个特定模块添加补丁，更不要试图通过修改测试代码来掩盖实现代码的问题！
- 如果确实需要修改测试代码（比如当前测试程序中存在一些不合理的地方），请通知我，在得到明确许可后再进行修改。
