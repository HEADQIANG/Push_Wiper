# 可独立运行且可无缝接入 Push-Wiper 的力控模块

## Summary

实现一个独立的执行层控制器，支持固定 XY、拖拽后 Y 轴往返和 NPZ 平面轨迹，并统一
保持 Z 向接触力。

核心控制采用论文中的二阶导纳模型：

```text
m * δ̈n + b * δ̇n + k * δn = Fdes - Fn
```

其中：

```text
Fn = -(FZ_raw - bias_FZ)
```

因为当前传感器向下受压时原始 `FZ` 为负。第一阶段目标力设为 5 N，后续可改为论文实验中的 20 N。

## 模块结构

新增独立 `airbot_ie/force_control/` 模块，并提供脚本：

在 `AIRBOT-Data-Collection` 目录使用独立启动入口：

```bash
scripts/start_force_hybrid.sh run
```

启动前可先执行 `scripts/start_force_hybrid.sh validate`，传感器和拖拽预览分别使用
`sensor-check` 与 `drag-preview`。完整的服务启动顺序见
`AIRBOT-Data-Collection/docs/setup/force_hybrid_control.md`。

模块分为四层：

- `KunweiKwr75Reader`：默认解析坤维 KWR75 串口帧并执行本地 tare；`LFS6D65Reader` 作为可选 Modbus 回退后端。
- NPZ 模式可通过 `trajectory.move_to_capture_pose=true` 先移动到 NPZ 中保存的初始观测位姿；启用 `staged_move_to_trajectory` 后，再分阶段移动到轨迹 XY、姿态和安全高度。
- `AirbotPlayAdapter`：封装连接、位姿反馈、规划位姿移动、`SERVO_CART_POSE` 命令和安全停止。
- `AdmittanceController`：实现论文二阶导纳、滤波、限幅和力方向转换。
- `PoseTrajectory`：提供期望位置、姿态和表面法向。第一阶段使用固定 XY，后续替换为 Push-Wiper 轨迹。

调试拖拽方向可使用 `--drag-preview`。该模式只进入重力补偿并实时绘制 SDK 末端参考点
的 X/Y/Z 曲线，不启动 LFS-6D65，也不会发送位姿移动命令；关闭窗口或按 `Ctrl+C` 后
退出重力补偿。

力控模块不直接依赖 Diffusion Policy 或 NPZ 文件，轨迹只通过统一接口输入。

## 独立力控阶段

当前配置还支持拖拽后 Y 轴往返模式：启动时进入重力补偿，操作者将末端拖到初始
位置并按 Enter 确认，控制器随后以 1 cm/s 峰值速度执行 `y0 → y0+0.10 m → y0` 的基座 Y 轨迹；接触后
仍使用 Z 方向法向导纳保持目标力。对应配置为
`trajectory.mode=drag_y_sweep`、`trajectory.y_distance_m=0.10`、
`trajectory.y_speed_m_s=0.01`、`trajectory.align_tool_z=false` 和 `drag.enabled=true`。

固定 XY 模式使用配置文件中的固定 XY：

```json
{
  "standalone": {
    "fixed_xy": [0.20, -0.10],
    "orientation": null,
    "safe_clearance_m": 0.02,
    "approach_speed_m_s": 0.002,
    "contact_threshold_n": 0.5
  }
}
```

执行流程：

1. 连接 Airbot 和 LFS-6D65。
2. 工具悬空，执行传感器硬件清零。
3. 采集约 2 秒数据计算软件零偏。
4. 读取当前姿态；`orientation=null` 时锁定当前姿态。
5. 移动到固定 XY 和安全高度。
6. 以 2 mm/s 向下接近，直到：

   ```text
   Fn > 0.5 N
   ```

7. 进入 `CONTACT_SETTLE`，保持约 0.5 秒并清空导纳状态。
8. 进入 `FORCE_HOLD`，固定 XY 和姿态，仅通过导纳修正法向位置。
9. 结束时向上抬升 20 mm，切换到安全保持状态。

独立阶段的轨迹提供器输出：

```python
TrajectoryPoint(
    position_base=[fixed_x, fixed_y, z_reference],
    orientation_xyzw=current_orientation,
    normal_base=[0.0, 0.0, 1.0],
)
```

当前水平桌面取基座 Z 轴为表面外法向，导纳位移沿负 Z 方向进入表面：

```text
p_command = p_tracking - normal_base * δn
```

`p_tracking` 的法向分量取轨迹参考，切向分量按实测位置和切向限速计算；不能用当前
实测法向位置替代参考后再次减去累计 `δn`。当前三种平面轨迹在检测接触时固定参考 Z，
因此法向目标始终满足 `z_command = z_reference - δn`。

## 二阶导纳实现

每个 100 Hz 控制周期执行：

```text
e = F_target - F_normal

v_next = (m * v_delta + dt * (e - k * delta)) / (m + b * dt + k * dt**2)
v_delta = clamp(v_next,
                -max_retract_speed,
                 max_press_speed)

delta = clamp(delta + v_delta * dt,
              -max_retract_displacement,
               max_press_displacement)
```

这里使用后向欧拉积分，同时保留速度和位移限幅；位移越界被裁剪时清零速度并进入
故障处理。首步使用配置周期，其余步使用实际单调时钟间隔，接触稳定后重新开始调度，
避免追赶旧周期造成额外积分。后向欧拉解决默认 100 Hz 下原半隐式欧拉的数值振荡，
不改变虚拟刚度带来的平衡关系 `delta = e / k`。

初始配置：

```text
control_hz                 100
target_force_n              5.0
force_sign                 -1
filter_cutoff_hz            2.0
mass_kg                     0.05
damping_ns_m                10.0
stiffness_n_m               500.0
max_press_speed_m_s         0.003
max_retract_speed_m_s       0.008
max_displacement_m           0.020
max_force_n                  8.0
sensor_stale_s               0.2
```

传感器实际约 14 Hz，采用独立线程读取并在 100 Hz 控制线程中使用最新滤波值。每个力样本必须携带单调时钟时间戳，超过 0.2 秒未更新时进入故障状态。

安全状态：

- `Fn > 8 N`：立即停止轨迹并抬升；
- 传感器数据无效或超时：停止继续下压并抬升；
- 导纳位移达到 ±20 mm：故障；
- Airbot 位姿反馈或命令失败：进入故障；
- 所有六维力数据持续记录，当前只使用 `FZ`，为后续力矩补偿保留接口。

## 后续 Push-Wiper 平面接入

后续新增 `PlanarPushWiperTrajectory`，实现与固定 XY 相同的接口：

```python
class PoseTrajectory(Protocol):
    def sample(self, t_s: float) -> TrajectoryPoint: ...
```

平面轨迹接入方式：

- 读取现有 `sample.npz` 的 `actions` 或 `actions_full`；
- `x/y` 使用仓库当前定义的执行臂基座坐标；
- `delta_yaw` 相对 `capture_reference_pose` 叠加；
- 平面表面法向固定为 `[0, 0, 1]`；
- TCP 姿态使工具 Z 轴保持朝向表面；
- 使用 B 样条或等价平滑轨迹；
- 使用梯形速度限制；
- 使用四元数 SLERP 插值姿态；
- 导纳控制器完全不变，只接收新的 `TrajectoryPoint`。

因此，后续执行层命令保持统一：

```text
p_cmd = p_current
        + tangential_tracking_error
        - normal_base * delta_n

R_cmd = R_trajectory
```

这对应论文中“切向位置跟踪 + 法向导纳修正”的结构。当前固定 XY 模式只是该接口的最小实现。

实现时必须读取仓库中的 `ACTION_DEFINITION`，明确处理 `x/y` 的基座坐标语义和 `delta_yaw` 的参考姿态，避免把仓库已导出的绝对位置误当成论文中的局部动作。

测试分为：

1. 纯算法测试：
   - 负 `FZ` 正确转换为正压入力；
   - 二阶导纳单步更新；
   - 稳态位移约为 `F_error / k`；
   - 默认周期及变周期下的收敛、零输入扰动衰减；
   - 速度、位移、最大力和传感器超时限幅。
2. 轨迹接口测试：
   - 固定 XY 输出；
   - NPZ 轨迹读取；
   - `delta_yaw` 相对捕获姿态计算；
   - 平面法向和姿态生成。
3. Mock 机器人测试：
   - `PRECHECK → MOVE_SAFE → APPROACH → CONTACT_SETTLE → FORCE_HOLD → RETRACT`；
   - 传感器失联和过力故障；
   - 连续执行、反馈滞后和位移回退时法向目标不重复累加；
   - 接触后周期调度及实测/命令位置日志区分。
4. 真机分阶段测试：
   - 仅传感器读取；
   - 空中固定 XY；
   - 1–2 N 接触；
   - 5 N 力保持；
   - 最后接入 Push-Wiper 平面轨迹。

## Assumptions

- 当前传感器 Z 轴与 Airbot 基座 Z 轴对齐。
- 向下受压时原始 `FZ` 为负，默认 `force_sign=-1`。
- 独立阶段使用配置文件中的固定 XY。
- 第一阶段固定姿态，后续平面 Push-Wiper 接入时启用 `delta_yaw`。
- 目标力当前为 5 N；论文一致性实验再将配置改为 20 N。
- 当前只实现平面执行层，不在本阶段实现曲面 ASPI 和后处理动作。

本方案以 Push-Wiper 论文中的 ASPI、切向位置跟踪和法向二阶导纳结构为后续接口依据：`:codex-file-citation{path="/home/wp/yuelk_project/Push_Wiper/Push-Wiper.pdf" purpose="source"}`。
